# 1단계 독립 검수

검수 기준: `01-MASTER-PROMPT.md`와 `stages/01-foundation.md`의 안전 원칙 및 완료 조건. Rust/UI 경계와 설정을 읽고 프런트엔드 빌드와 Rust 단위 테스트를 실행했습니다.

## 구현 후속 조치

### 수정됨 — 순회 중 읽기/권한 오류를 사용자에게 알리지 않음

- WalkDir, 메타데이터, 인덱스 기록 오류 건수를 모아 스캔 후 경로 없이 요약 경고를 보냅니다.

### 수정됨 — 취소 이후 인덱스가 부분 상태로 남음

- 인덱스 교체는 SQLite 트랜잭션으로 수행됩니다. 취소하면 롤백하고 `cancelled` 이벤트를 보내며 UI에서 부분 결과를 비웁니다. 롤백 보존 단위 테스트도 추가했습니다.

### Major — 스캔 명령이 UI가 전달한 임의 경로를 수용함

- 위치: `src-tauri/src/lib.rs:35-37`
- 명령은 경로를 canonicalize하고 하위 범위를 제한하지만, OS 폴더 대화상자에서 사용자가 선택했는지를 Rust가 검증하지 않습니다. 로컬 WebView에서 명령을 직접 호출하면 UI의 폴더 선택 흐름을 우회할 수 있습니다.
- 조치: Rust 측에서 선택 경로를 발급/등록하는 단일 경계로 바꾸고 스캔 명령이 등록된 경로만 받도록 합니다.

### Major — 파일마다 React 목록 전체를 갱신함

- 위치: `src/ui/App.tsx:15-17`
- 파일 이벤트 하나마다 새 배열을 만들어 전체 목록을 갱신합니다. 수만 파일에서 렌더링 비용과 메모리 사용이 커져 UI 응답성이 저하될 수 있습니다.
- 조치: 이벤트를 묶어 배치 반영하거나 가상 목록과 페이지 단위 렌더링을 도입하고 대량 합성 fixture로 측정합니다.

## 검증 결과

- 통과: `package.json`, `tsconfig.json`, Tauri 설정 및 capability JSON 구문 검사.
- 통과: TypeScript 검사 및 Vite 프로덕션 빌드 (`tsc --noEmit`, `vite build`).
- 통과: `cargo test --offline` (Rust 5개 테스트).
- 테스트 범위 누락: 빈 폴더, 루트 권한 오류, 삭제된 폴더 및 대량 UI 응답성은 자동 테스트에서 확인하지 못했습니다.
- 미실행: Rust 테스트와 OS별 수동 검증. Cargo 실행 도구는 준비했지만 `crates.io` DNS 조회가 실패해 Rust 의존성을 받지 못했습니다.

## 판정: 차단

빌드와 Rust 단위 테스트는 통과했고 macOS에서 Tauri 앱이 실행됐습니다. 다만 위 두 Major 위험과 대량/권한 fixture 공백, Windows 미검증이 남아 단계 승인은 차단합니다. 다음 구현 단계에서 경로 권한 경계와 목록 대량 처리 개선을 먼저 반영해야 합니다.
